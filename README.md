# 刷流追新

适用于 MoviePilot v2 的多站点 RSS 刷流与追新插件。所有站点共用一个 qBittorrent，可选择 MoviePilot 内置下载器或配置自定义 WebUI 连接。

## 功能

- 桌面任务表与手机任务卡；站点切换、搜索、状态筛选、记录分页、规则摘要与未保存修改提示。
- 每站点多条 RSS 任务，支持关键词、分辨率、发种时间、文件大小和免费促销筛选。
- 最高画质去重在所有站点间统一进行；持久化年份、季集与 RSS 副标题身份，避免重启后误合并。
- 升级时只暂停插件管理的旧版本；替代任务明确完成后才清理未完成旧版本，已完成内容保持做种。
- 替代失败时恢复由插件暂停的旧任务或启动备用版本；无完整副本时保留最后的未完成数据。
- 免费到期的最后未完成副本先暂停、保留文件；存在完整替代副本时才清理未完成任务。
- 顺序删种规则按任务标签、做种时间和分享率匹配；空标签表示不匹配，不会扩大到全部任务。
- RSS、免费期检查和删种有独立间隔，修改任务串行执行；活跃线程不会因为租约超时被重复启动。
- 状态查询只读；qB 快照短时缓存，RSS 批量添加共用快照并集中确认，避免逐条反复拉取全量任务。
- 配置加载失败禁用保存；保存期间新增输入保留为草稿。运行中保存的新配置在本轮结束后应用，不混用下载器。

## 安装

将本仓库地址添加到 MoviePilot v2 的第三方插件市场，或将 `plugins.v2/brushflowtracker` 安装为 v2 插件。插件源码已经包含 `dist/assets/remoteEntry.js` 前端构建产物。

安装后进入“全局设置”选择 MoviePilot 中已配置的 qBittorrent，或填写自定义 qBittorrent WebUI 地址和凭据。没有站点也可先配置下载器；手机可从站点选择器旁的“新增”建立站点。

更新到 1.1.24 后保留原有配置和运行数据，旧身份记录按保守方式补齐；信息不足的记录不会被猜测为同一季集并自动删文件。

## 配置语义

### RSS 选种

- “必须包含关键词”采用全部包含；“排除关键词”命中任意一个即排除，匹配标题与描述且忽略大小写。
- 分辨率支持 8K、4K/2160p、1080p、1080i、720p、576p、480p。
- “发种时间范围”单位为分钟，例如 `0–30` 表示只选择发布不超过 30 分钟的条目。配置范围但 RSS 没有可解析发布时间时会排除。
- “文件大小范围”单位为 GiB，例如 `0–30` 表示只选择不超过 30 GiB 的条目。配置范围但 RSS 没有可解析大小时会排除。
- 兼容站点把体积写在 RSS HTML 描述或 `length="4.01 GB"` 中的格式；PT 页面显示的 KB/MB/GB/TB 与规则使用相同的 1024 进制换算。
- 兼容对象型 enclosure、content/summary/subtitle 描述字段，以及描述中标注的“发布时间”。
- 免费促销可选不限、仅免费、免费或双倍上传免费、仅双倍上传免费。
- 任务名称必填且不能包含英文逗号。添加到 qBittorrent 时只使用任务名称这一个标签。

### 最高画质去重

启用最高画质去重后，所有站点的 RSS 候选统一按影视身份择优。同一分辨率还会比较 HDR、片源、编码和体积；开启避死种时区分确认无种与未知做种数，未知不会单独导致画质降级。影视身份保存年份、季、集范围和可解析副标题，技术字段不参与身份。

未确认的提交只占用临时状态；确认 hash 后才提交正式去重记录。新版本失败不会删除最后的未完成副本，已由插件暂停的旧版可受控恢复。用户手动暂停的任务不会被当成插件暂停任务强行恢复。

### 免费期

插件优先读取 RSS 中的 `freedate`、`free_until`、`free_end`、`promotion_end`，也支持从标题或描述解析“免费截止/Free until”和“免费剩余/Free remaining”。RSS 明确提供促销状态时严格筛选；RSS 无法确认状态时不逐条抓取详情页，而是按关键词、分辨率、大小和发种时间等其他规则继续添加。

### 自动删种

- 仅处理插件持久化记录中属于当前站点的 torrent hash，不会删除其他下载。
- 新增删种规则时会填入当前站点任务名称；选择多个标签时命中任意一个即可。显式清空标签或移除关联 RSS 不会改成匹配所有任务；前端会停用失去关联的规则。
- “执行删种”会先确认目标站点及是否删除文件，不是只读预览。手动操作使用已保存配置，有草稿修改时先保存。
- 做种时间和分享率同时达到阈值才匹配。
- 多条规则从上到下检查，命中第一条后停止。可分别选择是否同时删除文件。

## 数据与日志

去重记录、已处理 RSS 地址、托管任务、站点统计和历史均通过 MoviePilot 插件数据持久化。网络失败、qBittorrent 失败、RSS 过期、无法识别免费截止时间和删种结果都会写入 MoviePilot 日志。

待确认提交由后台新鲜快照对账，不会因多次打开页面消耗重试次数。失败确认至少间隔 15 秒；提交至少 60 秒且失败确认达到三次，或超过 300 秒仍未确认时，撤销本次占位和对应 URL 标记，允许仍符合规则的 RSS 条目重试。并发保存会合并并补写更新的状态，保存失败保留待补写状态。

RSS 刷新时，每个条目都会输出一条结构化日志，包含站点、任务、结果、原因、种子名称和下载链接。结果覆盖规则排除、同站点低画质、历史去重、添加成功与 qBittorrent 添加失败。管理页的“处理记录”会展示已添加种子，点击名称可打开站点详情页。

## 开发验证

后端规则与集成测试（Python 3.12，MoviePilot/qB/RSS 使用离线替身）：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

前端单元测试与构建（Node 22、pnpm 9.15.9）：

```bash
corepack enable
corepack prepare pnpm@9.15.9 --activate
cd plugins.v2/brushflowtracker
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

提交中包含 MoviePilot 模块联邦需要的 `dist/assets/remoteEntry.js`；发布时使用干净构建输出，不混入旧 hash 文件。

GitHub Actions 模板位于 `docs/ci/verify.yml`，覆盖后端测试、前端交互测试与构建检查。启用自动验证时，在 GitHub 网页中将模板添加为 `.github/workflows/verify.yml`。本地测试与插件安装不依赖 Actions。
